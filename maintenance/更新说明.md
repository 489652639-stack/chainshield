# 自动维护的能力与边界

应用在启动、返回前台及前台使用期间定期检查维护配置。成功后六小时再检查；失败后至少间隔十五分钟再自动重试。手动检查可立即重试。关闭应用后不会持续后台运行。

在线更新仅支持经过固定公钥签名验证的数据：官方接口版本路径、缺失字段的兼容别名、数据源维护开关、明确的费率单位和中文词库。已有字段不会被别名覆盖。未知内容保持未知，不通过猜测消除风险。

签名失败、旧版重放、重复字段、过期、超大数据、陌生域名及不兼容配置均拒绝接受。失败时保留仍有效的上次配置，过期后退回内置配置。接受新配置后连续三次完整查询均无可用来源时，隔离该配置并回退内置配置；若发布方明确停用了数据源，则不自动解除停用。回滚已发布内容须重新签发更高版本序号。

没有下载执行任意脚本或任意程序代码。核心逻辑变化仍需新版安装包。应用只提示并打开经过签名确认的 GitHub 发布页；安装操作由用户在安卓系统中确认，应用没有静默安装权限。发布页校验不等于应用已下载并自行计算安装包哈希，安装包签名最终由安卓系统验证。

实际更新地址为 `https://raw.githubusercontent.com/489652639-stack/chainshield/main/updates/channel.json`。1.6.1 已内置此地址；1.6 可在“自动维护”的设置中连接同一地址。无需额外开通 Pages。

持续自动续签需要在仓库 Actions Secrets 中配置维护私钥；固定签名 APK 自动发布还需要安装包签名相关保密项。没有这些保密项时只能运行检查，不能把首次手动签发称为长期自动发布已上线。

自动化会检查六项真实接口及离线回归，通过后才签发维护配置。API 故障会阻止发布并保存检查结果。自动流程不能自行设计任意新接口、取得服务商授权或保证修复所有未来错误。公众仓库的定时任务可能因 GitHub 策略暂停，维护者仍需定期核查。

## 部署所需保密项

- `MAINTENANCE_PRIVATE_KEY`：维护签名私钥，必须匹配应用内的 `maintenance-public.der`。
- `CHAINSHIELD_KEYSTORE_BASE64`、`CHAINSHIELD_STORE_PASSWORD`、`CHAINSHIELD_KEY_PASSWORD`、`CHAINSHIELD_KEY_ALIAS`：固定安装包签名。
- 可选的服务商授权项：`GOPLUS_ACCESS_TOKEN`、`HONEYPOT_API_KEY`、`RUGCHECK_API_KEY`。手机端不自动取得 CI 私密凭证；服务商将来要求授权时需要另行设计授权配置。

私钥备份单独交付，未放入公开源码压缩包或在线配置。自动维护密钥与安装包签名密钥分别生成。
